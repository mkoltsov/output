What the review establishes

This report records the initial cloned snapshot; subsequent task work is outside its scope. The technical analysis covered tracked instructions, skill definitions, Python implementations and tests, local nutrition storage, training documents, language lessons, and audio. Existing tests ran against mocked services or temporary data. Additional synthetic probes exercised suspected defects without submitting records or authenticating to external services.

The source JSON contains seven recorded days and 45 uniquely identified consumed meals. SQLite integrity and foreign-key checks passed. All four tables and two views matched a fresh temporary rebuild. The 45 local synchronization receipts matched the source calorie and macro values and carried historical verification timestamps. This establishes internal consistency and historical receipt agreement; it does not establish the current state of a remote account.

The existing suite comprises six food-log tests, seven diet-review tests, eight health-check tests, 15 Costco tests, and eight Technogym tests. Passing those tests supports their specific assertions. Synthetic probes below show why that result should not be interpreted as comprehensive production verification.

Evidence labels: “Confirmed” means demonstrated from current files, local checks, or synthetic execution. “Documented” means stated in repository prose. “Unverified” identifies a live-state or provenance claim that this audit did not establish.

How the components fit together

Local source and projection

Food logging and diet review

food-log records consumed food, maintains synchronization receipts, and can submit entries to Google Health. daily-diet-review interprets the local record. SQLite is a derived projection rather than a fully faithful copy of every source field.

Read-oriented connectors

Health, purchases, and training

fitbit-health-check summarizes wearable records. costco-purchases retrieves purchase history and renews stored authorization when necessary. technogym-workouts reads completed machine sessions. Query POST requests are constrained to read endpoints; token renewal still has local side effects.

The repository instructions require primary-evidence checks, independent interpretation, delegation, and responsive communication. These are useful operating rules, although they depend on the active agent reading and applying them. All five skill definitions exist on disk; their presence does not make them automatically advertised or enabled. The corresponding user-local skill symlinks were absent in the inspected setup.

Several instructions assume an earlier cloud runtime, host arrangement, or installation location. The root README still presents a small Polish-learning project and does not describe the current health, nutrition, purchases, training, and music responsibilities. A new maintainer therefore receives an incomplete entry point.

Concrete reliability and security findings

High · confirmed synthetically

Concurrent food synchronization can submit the same meal twice

Two runs can read the same initial receipt ledger and remote state before either records its result. A synthetic concurrency probe produced two submissions for one meal. Atomic replacement protects the receipt file from a partial write; it does not serialize the complete read, decide, submit, verify, and persist transaction.

Use a single-writer lock across the whole operation and investigate a supported remote idempotency mechanism. Recovery must reconcile ambiguous submissions before retrying. Add a concurrent-run regression test and a crash-between-submission-and-receipt test.

Evidence: .agents/skills/food-log/scripts/sync_google_health.py:170 and :201; ledger loading and submission operate without a surrounding transaction lock.

Medium · confirmed

The same missing status has three incompatible interpretations

For schema version two, SQLite defaults a missing consumption status to consumed, diet review rejects the record, and synchronization omits it. A malformed entry can therefore count locally, prevent review, and disappear from the remote upload selection. The current source data reconciles, but the shared contract is not enforced consistently.

Centralize schema validation before projection, review, and synchronization. Require explicit status in the newer schema and preserve legacy defaults only where migration rules authorize them.

Evidence: nutrition/build_database.py:84; .agents/skills/daily-diet-review/scripts/review_day.py:22; .agents/skills/food-log/scripts/sync_google_health.py:37.

Medium · confirmed

The SQLite projection loses source semantics

Meal-level explicit calories, optional nutrients, and meal type are not fully represented in the database. Its macro-derived energy views can therefore differ from the source’s explicit estimate without preserving enough context to explain the difference. Rebuilding the database successfully proves reproducibility, not semantic completeness.

Either extend the projection with those fields and their provenance or state clearly that SQL consumers receive a deliberately reduced dataset. Preserve the distinction between an unknown nutrient and a measured zero.

Evidence: nutrition/build_database.py:29, :47, and :80; compare the review’s explicit-calorie handling at review_day.py:27.

Medium · confirmed synthetically

Health checks validate numeric finiteness without adequate domain checks

A finite negative heart-rate sample is accepted by the summarizer. Finite numbers are not necessarily valid measurements. Each metric needs an appropriate structural and domain rule, with impossible values rejected or marked invalid instead of incorporated into trends. Plausibility checks should remain data-quality checks rather than medical diagnoses.

Evidence: .agents/skills/fitbit-health-check/scripts/check_health.py:25 and :71.

Medium · confirmed synthetically

Sleep deduplication and freshness can conceal conflicting evidence

Records with the same interval but conflicting sleep totals silently retain the first value. Separately, a recent nap can make the shared sleep freshness flag appear current while the latest main sleep is substantially older. That flag does not reliably answer whether the main overnight measurement is current.

Detect conflicts explicitly, preserve source or revision metadata, and calculate freshness separately for main sleep and naps. Reports should distinguish unavailable, stale, conflicting, and valid evidence.

Evidence: .agents/skills/fitbit-health-check/scripts/check_health.py:101, particularly interval deduplication and the shared freshness result at :128.

Medium · confirmed synthetically

A Technogym export can replace its own credential file

The command accepts the same path for credentials and output. A synthetic invocation completed successfully and replaced its synthetic credential file with a report. The Costco helper already guards against this collision. Validate the destination before authentication, including resolved paths, and reject credential-file aliases.

Evidence: .agents/skills/technogym-workouts/scripts/pull_sessions.py:299 and :308; replacement occurs at :272.

Medium · confirmed synthetically

Workout pagination can report completeness too early

An empty history page ends retrieval even when the response contains a continuation cursor. A synthetic probe confirmed that the next page is never requested. Collection can then retain its default complete status. It is unverified whether the live service currently emits this combination; the implementation nevertheless fails to distinguish an inconsistent page from a verified end of history.

Evidence: .agents/skills/technogym-workouts/scripts/pull_sessions.py:161; completeness defaults at :224.

Medium · confirmed

Malformed nested workout records escape the intended error path

The parser checks that activities form a list but assumes its elements and nested performance data are dictionaries. A synthetic null activity raises an uncaught attribute error rather than the connector’s sanitized, completeness-aware exception. Validate each nested structure and convert schema failures into the defined error type.

Evidence: .agents/skills/technogym-workouts/scripts/pull_sessions.py:197 and :321.

Medium · contextual security risk

Credential protection depends on the containing environment

Three tracked base64 credential stores are documented as explicitly authorized. Base64 is reversible. The inspected copies use mode 0664, although the containing home directory currently uses 0700 and blocks ordinary traversal by other users. No exposure or unauthorized access was demonstrated. A later copy, permission change, backup, or differently configured clone could weaken that protection.

Prefer an external secret store where practical. Otherwise define a private post-clone permission step, restrict repository access, and retain the documented rotation procedure. Generated exports and rotated-token writes use owner-only temporary files, which does not automatically protect freshly cloned files.

Evidence: tracked-file and filesystem metadata; credential-storage explanations in training/README.md:15 and the relevant skill authentication sections. Credential contents are excluded from this report.

Lower priority · confirmed synthetically

Civil-time arithmetic can create the wrong elapsed interval

A nominal one-second synchronization interval crossing a daylight-saving transition represented 3601 elapsed seconds in a synthetic probe. Perform elapsed-time arithmetic in UTC and then format the required representation. Test both seasonal transitions and ambiguous civil times.

Evidence: .agents/skills/food-log/scripts/sync_google_health.py:181.

Operational gap · source inspection

Instrumentation and installation are not self-contained

No connector source integration with the required OTel bootstrap, sampling, textfile metrics, or digest failure reporting was found. An external wrapper was not verified. Add this coverage when changing or operationalizing the critical paths; do not infer that metrics already exist. No new scheduler is needed for these on-demand skills.

Health read scopes are underdocumented, and a generic write scope does not establish permission to retrieve every metric. Document the actual required scopes and validate them separately. Local symlink installation and dependency selection also need a reproducible entry point.

Learning materials, plans, and audio

Polish lessons need editorial repair

Six text files contain 179 lines in total; one grammar file is empty. A second exercise is blank and there is no answer key or defined progression. The translation of bardzo should be “very,” and the greeting should be Jak się masz? Widespread missing diacritics and spelling problems would teach incorrect forms if reused unchanged.

Add corrected examples, explicit objectives, completed exercises, and answer keys before treating the lessons as a course. The WSJP entry for bardzo and greeting entry support the cited corrections.

Audio is technically playable; provenance is incomplete

All three MP3 files decoded successfully. Two last approximately 1800.046 seconds and the preview lasts 60.029 seconds; each is 44.1 kHz stereo at 192 kbit/s. Tracked content totals approximately 88.215 MB, primarily audio.

Generation scripts and stems are absent. Subjective quality, originality, and the claimed tempo were not established. Public-domain dataset information in the cited voice model card corroborates documentation about that dataset, but does not prove which assets or process produced these files.

Nutrition documentation mixes current and historical descriptions

The synchronization section contains stale meal counts compared with current source tables and receipts. Keep dated menu proposals clearly separate from consumed records. Portion arithmetic is internally correct under the stated assumptions; labels, available stock, and current purchasing conditions were not live-verified. Some legacy measurements require conversion for metric presentation.

Food-storage suggestions should use food-specific limits and temperature conditions rather than a universal batch duration. Relevant public references are cold storage charts and safe handling steps.

Training records require careful interpretation

The sleep routine is a dated, on-demand proposal with no automatic reminders. Its historical baseline appears in prose; a supporting raw export is absent from the training materials. Its existence does not establish adherence or a current outcome.

The workout connector correctly preserves displayed source loads when raw values and unit labels disagree. User-facing summaries should derive metric presentation from the authoritative displayed value while retaining provenance. Recorded sets remain distinct from full working sets; repeated machine entries should not be silently collapsed.

A practical repair order

  1. Protect submission integrity: serialize food synchronization, reconcile ambiguous writes, and add concurrency and crash-recovery tests.
  2. Unify the record contract: share schema validation and preserve explicit energy, nutrient coverage, status, and meal-type semantics across consumers.
  3. Make readers fail clearly: validate metric domains, separate sleep freshness, flag conflicts, and repair workout pagination and nested parsing.
  4. Prevent local damage: reject credential/output collisions and make private post-clone permissions explicit.
  5. Make maintenance reproducible: refresh installation and scope documentation, add critical-path observability, correct the lessons, and document reproducible audio provenance.

These are proposed changes, not completed repairs. The current analysis applied no source changes and created no service, timer, cron job, or persistent background process.

What remains unverified

This technical audit used offline tests, current local records, and isolated synthetic probes. It did not establish a current remote record inventory, delivery, or live food synchronization. Historical receipt verification and repository statements about earlier successful runs remain historical evidence. Separate authorized credential checks are outside this report’s scope and are not included.

The official Google Health data-point list reference and create reference describe the relevant interface surface; documentation alone does not prove account scopes or a successful transaction. Unofficial purchase and workout interfaces can change independently of passing local tests.
